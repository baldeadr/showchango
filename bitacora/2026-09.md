### 2026-09-18 — F0: nace el repo de Show Chango

**Qué hice:**

- Creé el repo independiente `~/Projects/showchango` con `git init`, `.gitignore`, `pyproject.toml` y `Dockerfile` base.
- Escribí la documentación base: `README.md`, `AGENTS.md`, `docs/ARQUITECTURA.md`, `docs/FASES.md` y `docs/ESQUEMA-JSON.md`.
- Implementé el esquema JSON v1 en `src/showchango/core/esquema.py` con validaciones y round-trip.
- Levanté el esqueleto FastAPI: home, crear set, set vacío en sesión temporal RAM y exportar JSON.
- Verifiqué que `pytest`, `ruff check` y `uvicorn` funcionen.

**Qué aprendí:**

- Al decidir que **nada se almacena** (sets temporales, JSON como persistencia), la arquitectura se simplifica drásticamente: no hay cuentas, no hay tokens de enlace, el deploy en free tier no requiere disco persistente y la privacidad se convierte en diferenciador de producto.
- El esquema JSON v1 debe definirse primero y congelarse: es el contrato del round-trip y la base para que cualquier motor de análisis (librosa, Essentia, Essentia.js) pueda alimentar la misma estructura de setlist.

**Decisión tomada:**

- Show Chango tiene su propio repo (`~/Projects/showchango`) y su propia bitácora; la ficha de `architecting-a-band/show-chango/README.md` pasa a ser archivo histórico.
- Stack confirmado: FastAPI + HTMX + SortableJS + Chart.js + librosa + ThreadPool + WeasyPrint + matplotlib + SQLite solo como caché de análisis.
- Spotify/metadata fuera del MVP; entra en F2.
- Nada del usuario se persiste: sesión temporal + JSON exportado como única persistencia real.
