### 2026-09-18 — F0: nace el repo de Show Chango

**Qué hice:**

- Creé el repo independiente `~/Projects/showchango` con `git init`, `.gitignore`, `pyproject.toml` y `Dockerfile` base.
- Escribí la documentación base: `README.md`, `AGENTS.md`, `docs/ARQUITECTURA.md`, `docs/FASES.md` y `docs/ESQUEMA-JSON.md`.
- Implementé el esquema JSON v1 en `src/showchango/core/esquema.py` con validaciones y round-trip.
- Levanté el esqueleto FastAPI: home, crear set, set vacío en sesión temporal RAM y exportar JSON.
- Verifiqué que `pytest`, `ruff check` y `uvicorn` funcionen.

**Qué aprendí:**

- Al decidir que **nada se almacena** (sets temporales, JSON como persistencia), la arquitectura se simplifica drásticamente: no hay cuentas, no hay tokens de enlace, el deploy en free tier no requiere disco persistente y la privacidad se convierte en diferenciador de producto.
- El esquema JSON v1 debe definirse primero y congelarse: es el contrato del round-trip y la base para que cualquier motor de análisis (librosa, Essentia, Essentia.js) pueda alimentar la misma estructura de setlist.

**Decisión tomada:**

- Show Chango tiene su propio repo (`~/Projects/showchango`) y su propia bitácora; la ficha de `architecting-a-band/show-chango/README.md` pasa a ser archivo histórico.
- Stack confirmado: FastAPI + HTMX + SortableJS + Chart.js + librosa + ThreadPool + WeasyPrint + matplotlib + SQLite solo como caché de análisis.
- Spotify/metadata fuera del MVP; entra en F2.
- Nada del usuario se persiste: sesión temporal + JSON exportado como única persistencia real.

**Siguiente paso:**

### 2026-09-18 — F1-M1: importar pistas (manual, CSV/Excel, audio, JSON)

**Qué hice:**

- Agregué `librosa`, `openpyxl` y `soundfile` al stack; `Dockerfile` ahora instala `ffmpeg`.
- Creé el módulo `analytics` con la interfaz `Analyzer` y su implementación `LibrosaAnalyzer` (BPM, duración, energía, loudness, bailabilidad heurística, valencia por modo mayor/menor, tonalidad por Krumhansl-Kessler).
- Creé la caché de análisis por hash en SQLite (`showchango/db/__init__.py`) para no repetir análisis.
- Implementé en la web: formulario manual de pista, edición de atributos, eliminación, importar CSV/Excel, importar JSON (round-trip), y subida de audio con análisis en background + HTMX polling.
- Actualicé las plantillas (`set.html`, `index.html`, `analisis_estado.html`) y los estilos.
- Agregué tests para todas las vías de importación, incluyendo audio sintético a 120 BPM. Total: 23 tests, `ruff check` limpio.

**Qué aprendí:**

- librosa 1.0 cambió la API: `librosa.feature.rhythm.tempo` reemplaza al antiguo `librosa.beat.tempo`; hay que importar el submódulo `rhythm` explícitamente.
- TestClient de FastAPI ejecuta las `BackgroundTasks` antes de devolver el response, lo que simplifica los tests de análisis asíncrono.
- Mapear encabezados de CSV/Excel con y sin tildes hace la importación usable con hojas reales del artista.

**Decisión tomada:**

- Los atributos de librosa son un punto de partida editable; la UI deja cambiar cualquier campo. La caché solo guarda atributos anónimos por hash, nunca audio.
- El análisis de voz/instrumental queda como `[PENDIENTE]` para un modelo posterior; por ahora `voz` es `None` y el usuario lo indica a mano.

**Siguiente paso:**

- F1-M2: curva + drag & drop (SortableJS + Chart.js).
